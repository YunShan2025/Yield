# 修改记录

本文件是「有秋（Yield）」的主变更档案，记录应用的**所有**代码、配置与文档改动。每次改动后必须在「修改记录」区倒序追加条目。

- **当前版本**：v1.0.0（`package.json` / `src-tauri/tauri.conf.json`）
- **相关文档**：`README.md`（产品与版本说明）、`docs/PRODUCT_DECISIONS.md`（产品需求与决策记录）

## 记录约定

1. **倒序追加**：最新条目放在「修改记录」区的最上面。
2. **条目完整**：每条包含类型、改动内容(涉及文件,尽量标注函数/行号)、原因、影响、验证方式。
3. **数据库变更单独强调**：涉及 SQLite 表结构或 migration 时,必须在「影响」中注明 migration 编号,并确认 `src/lib/db/` 的迁移逻辑与 `docs/PRODUCT_DECISIONS.md` 同步更新。数据库结构只支持向前升级,不支持降级。
4. **README 同步**：影响用户可感知行为的修改,需同步更新 `README.md` 的版本说明;若发布新版本,版本号需同步改 `package.json` 与 `src-tauri/tauri.conf.json`。
5. **验证后才算完成**：条目落笔前至少跑 `npx tsc -b` + `npx vitest run` + `npx vite build`;涉及 Rust 的改动加 `cargo check`;界面改动需 `npm run tauri dev` 实机验证。
6. **改动必须彻底,杜绝代码空放**：任何功能改动都要前后端同步——删除或替换一个功能时,必须同步删除其对应的后端逻辑、数据库读写、store 方法、lib 纯函数、样式与无用导出,不允许留下只被前端引用或只被后端定义的"半截"代码;新增逻辑同理,分层职责要完整。`npx tsc -b`(noUnusedLocals)只能查局部未用变量,无用导出需人工 grep 确认零引用。

## 条目模板

```markdown
### YYYY-MM-DD · 一句话标题

- **类型**:功能 / 修复 / 重构 / 配置 / 文档 / 环境
- **改动**:`文件路径` — 改了什么(函数名或行号)
- **原因**:为什么要改
- **影响**:对数据结构 / 兼容性 / 其他模块的影响;无则写「无」
- **验证**:门禁结果、手动验证步骤
```

# 版本记录

本文件是「有秋（Yield）」的**版本记录**（面向使用者的版本历史，发布 Release 时同步维护）。

- **当前版本**：v1.3.0（`package.json` / `src-tauri/tauri.conf.json`）
- **相关文档**：`README.md`（产品说明）、`docs/ARCHITECTURE.md`（架构与技术栈）、`docs/GIT_CONVENTIONS.md`（推送与发布惯例）

## 记录约定

1. **倒序追加**：最新版本条目放在「版本记录」最上面，标题格式为 `#### v{版本号} 标题`。
2. **数据库变更单独强调**：涉及 SQLite 表结构或 migration 时，在版本条目中注明 migration 编号。数据库结构只支持向前升级，不支持降级。
3. **README 同步**：影响用户可感知行为的修改，需同步更新 `README.md` 的功能描述；发布新版本时版本号同步改 `package.json`、`src-tauri/tauri.conf.json` 与 `src-tauri/Cargo.toml`。
4. **验证后才发布**：发布前至少跑 `npx tsc --noEmit` + `npx vitest run` + `npx vite build`；涉及 Rust 的改动加 `cargo check`；界面改动需在模拟器/实机验证。

## 版本记录

#### v1.4.0 目标 · 习惯 · 事项打通

> 目标定位：**目标是里程碑式的长期最终结果；重复性归习惯；任务是一次性行动**。完整评估与方案见 [docs/GOAL-HABIT-TODAY-LINKAGE.md](GOAL-HABIT-TODAY-LINKAGE.md)。

- **目标重新定位为里程碑（migration v22）**：目标是长期的最终结果，不再承载任何周口径，界面上也不再让用户选「目标类型」。内部按三种判据推进——数值·次数（起点→目标值）、数值变化（最新一次测量）、阶段（可勾选的阶段清单）
- **目标类型归并**：`quantity` / `change` / `custom` / `frequency` / `time` / `project` 六种旧类型归并为 `milestone` / `measure` / `staged`；未升级的对端发来的旧类型在落库前归一，不会静默丢数据
- **项目型目标退役**：它只是项目完成率的镜像（项目做到 90% 不等于离目标近 90%），完成率先固化成一条记录再转成 0→100% 的数值目标；项目本身与任务不受影响，进度仍在项目页可见
- **任务删除重复字段（migration v22）**：重复性的事一律建习惯。`tasks.repeat_rule` 与 `tasks.generated_from_id` 两列下线，带重复规则的任务先转成对应习惯，原任务软删除进回收站（可恢复，不丢用户数据）
- **习惯接管重复能力（migration v22）**：新增 `habits.repeat_rule` 排期规则（每天 / 每周指定几天 / 每周若干次）。固定排期的习惯只在该出现的日子进入今日事项；「每周几次」在固定排期下由排期推算
- **关联改为「服务」而非「计量」（migration v22）**：任务与习惯关联目标后默认**只关联、不计数**；需要计数时显式声明「算 1 个单位」或自定义单位数。同一动作至多计量一个目标，从根上消灭「一件事记两遍」
- **目标详情页新增「阶段」与「正在推进」**：阶段清单把大目标拆成可勾选的阶段，勾一个进一个；「正在推进」列出关联的任务与习惯，并可当场切换每一项是否计入目标
- **目标分母统一到唯一真源**：新增 `resolveGoalTarget` / `calculateGoalProgress`，今日目标条、目标卡、成长页、习惯页、复盘页全部走同一处取数。旧代码里各界面各取一套分母，于是同一个目标在今日页显示「4/2」而进度条按另一个分母算成满格
- **目标表单移除「每周目标次数」**：周口径整体归习惯；目标卡脚注不再回显无效的「每周 N 次」
- **复盘页两处目标统计不再同名不同义**：「当周目标推进」列出每个目标当周积累的进度及其构成（任务 / 打卡 / 记录），「任务完成去向」按目标 / 项目 / 标签查看当周完成的任务归属
- **成长热点图按目标筛选真正生效**：此前只筛手动记录，任务与习惯仍按全量点亮；现在按目标的关联关系同步筛选
- **今日页新增「本周节拍器」**：一行说完这周的投入——几次打卡、几件事完成、连续多少天，把「今日」与「本周」两个坐标系对齐
- **首启引导新增一步**：「目标、习惯、任务各司其职」——目标拆阶段、重复建习惯、一次性建任务
- **数据库结构变更（migration v22）**，只向前升级、不支持降级：新增 `habits.repeat_rule`；删除 `tasks.repeat_rule`、`tasks.generated_from_id`、`goals.weekly_target`、`goals.project_id`
- **同步日志格式升版（schema v10）**：`tasks` 的重复相关列与 `goals` 的周口径列不再携带，`habits.repeat_rule` 入列。旧端读到 v10 条目会被 header 闸门整体拒收并提示升级，**两端需同时升级**

#### v1.1.3 项目标签同步收尾与移动端详情重叠修复

- **修复项目标签徽标在部分设备上显示为「标签」**：新设备首次启动会先生成一套默认标签，与另一端同步来的同名标签靠「收养」机制归并——此前该机制漏改了项目的标签引用，导致项目详情与标签关联显示不出来。现在同步时项目的标签引用会正确映射到本机标签，升级后首次同步会自动修复存量数据
- **修复移动端项目详情重叠**：点击项目卡片展开「xxx 的任务」后，详情区不再与上方区块重叠（此前滚动容器行高被压缩导致内容互相叠压），超高内容改为正常滚动
- 桌面端与 Android 端同步更新，可直接覆盖安装；升级后首轮同步会自动完成数据修复

#### v1.1.2 同步格式升版：项目标签补达与移动端项目页修正

- **项目标签补推**：升级到本版后，每个设备会把带标签的项目再补推一次同步——此前对端若在旧版本下消费过补发条目（同步水位已推进），标签仍然缺失；现在升级并同步一轮即可拿到
- **同步格式升版（日志 schema v3）**：旧版本应用拉到新格式日志时不再静默丢弃新增字段（这正是此前标签丢失的根因），改为明确提示「远端数据版本更高，请先升级本端」；升级顺序不再敏感，两端先后升级都能收敛
- **修复移动端项目页**：点击项目卡片展开详情后，「项目」标题行与项目卡片不再被压没、详情不再紧贴引导框（内容超高改为正常滚动）
- 同步日志格式有升版：请双端都升级到 v1.1.2；旧版本同步时会收到升级提示
- 桌面端与 Android 端同步更新，可直接覆盖安装

#### v1.1.1 修复项目标签不跨设备同步

- 修复项目的所属标签同步不到另一端的问题（migration v11）：v1.1.0 的迁移回填不改更新时间，而同步触发器只在更新时间变化时记录改动，导致回填的标签从未进入同步日志；安卓端又在旧版本下消费过更早的日志条目，标签从此缺失。现在升级时会把带标签的项目重新推入同步队列，下一轮同步自动补发
- 修复全新设备首次「存量数据首接入」可能因已下线的数据表报错的问题
- 需要 v1.1.1 及以上版本之间同步；旧版本拉取新日志不会出错，但请尽快双端升级
- 数据库结构有变更（migration v11），只向前升级、不支持降级；桌面端与 Android 端同步更新，可直接覆盖安装

#### v1.1.0 项目标签与页面同构、下线项目成果/里程碑

- **项目标签**（migration v9）：项目可绑定标签，选中项目的任务默认继承该标签；新建/编辑项目可选择标签
